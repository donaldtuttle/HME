## Why this file exists

HME originated inside the QOSMOS research stack and still exposes names that
map to QOFT/QOSMOS operators. The public README now explains HME as a standalone
memory engine first; this document preserves the technical crosswalk for readers
who need framework integration details.

The crosswalk does not:

- amend QOFT/QOSMOS canon;
- promote HME into canon;
- prove that an HME implementation exhausts any canonical operator;
- turn implementation telemetry into consciousness or physical evidence; or
- transfer license terms between HME and `qoft-calculus`.

## HME-local vocabulary

### QMesh

`QMesh` is the HME lineage graph. It records relationships among memory,
collapse, and replay artifacts. It is an implementation structure, not a new
canonical QOFT space.

### `Ψmeta_pre`

`Ψmeta_pre` fields are computed before the realization-local collapse predicate
when they may later explain or influence that decision. The final HME tick
record is emitted after the decision. This ordering prevents post-hoc telemetry
from masquerading as pre-decision evidence.

### `W(t)`

`W(t)` is a visualization and diagnostic projection. It is not a physical
coordinate and does not establish a new field quantity.

### C(ψ) salience channels

The active engine contains three optional, default-off DEVELOP switches:

```text
W  influence_write_gain
R  influence_retrieval
I  enable_inscription_rejection
```

Their C0-C7 factorial harness is under `experiments/`. Implementation and
measurement do not establish efficacy. Any claim must stay scoped to the tested
condition, corpus, engine pin, protocol pin, answer key, and seed/config pin.
